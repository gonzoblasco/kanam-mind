# Auditoría de Entradas — 2026-08-17

> Verificación del comportamiento real del CRUD de entradas contra su spec (`openspec/specs/entradas/spec.md`).

## Resumen

El CRUD de entradas cumple **todos** los requirements del spec. No se encontraron bugs funcionales.

## Requirements verificados

### ✅ Requirement 1: El usuario crea una entrada con un tipo
- **Selector de tipo accesible:** `EntryModal.tsx` usa radios nativos (`<input type="radio">` con `sr-only`) dentro de un `radiogroup`. Verificado en browser (snapshot muestra `radiogroup "Tipo de entrada"` con 5 radios).
- **Nota:** textarea de contenido libre.
- **Check-in:** 3 sliders (ánimo/energía/sueño, 1-5) + nota opcional.
- **Idea:** textarea de pensamiento fugaz.
- **Writing:** input numérico de word count.
- **Foto:** input file (data URL) + caption opcional.
- **Guardado:** `handleSave` construye el `Entry` con `meta` según tipo y llama `putEntry`. Verificado en browser (creé una nota y apareció en el timeline).

### ✅ Requirement 2: El usuario edita una entrada
- **Datos precargados:** `handleOpenChange` carga `editing.type`, `editing.content`, metadata y `editing.tagIds` al abrir. Verificado en browser (el modal de edición mostraba el contenido existente).
- **updatedAt se renueva, createdAt se conserva:** `base.updatedAt = now`, `base.createdAt = editing?.createdAt ?? now`.

### ✅ Requirement 3: El usuario elimina una entrada
- **Confirmación accesible:** `ConfirmDialog` (Radix Dialog) con foco gestionado. Verificado en browser (diálogo "Eliminar entrada" con botones Cancelar/Eliminar).
- **Eliminación:** `deleteEntry` borra de IndexedDB solo al confirmar.

### ✅ Requirement 4: El usuario asigna tags a una entrada
- **Selector de tags:** `EntryModal` muestra chips toggle de tags disponibles (solo si `tags.length > 0`).
- **Persistencia:** `selectedTagIds` se guarda en `base.tagIds`. Verificado en `db.test.ts` ("una entrada puede tener múltiples tags").

## Hallazgos

Sin hallazgos. El CRUD cumple la spec completa.
