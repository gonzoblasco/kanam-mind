# Auditoría de Settings — 2026-08-17

> Verificación del comportamiento real de settings contra su spec (`openspec/specs/settings/spec.md`).

## Resumen

**PARCIALMENTE IMPLEMENTADO.** La capa de config de Ollama existe en `lib/ollama.ts` (get/save config
en localStorage), pero no hay modal de settings en la UI. El botón "Configuración" del header es un
placeholder (TODO).

## Requirements verificados

### ⚠️ Requirement 1: El usuario configura Ollama
- **Capa de datos:** `lib/ollama.ts` tiene `getOllamaConfig`/`saveOllamaConfig` (localStorage) y `DEFAULT_OLLAMA_CONFIG` (baseUrl `http://localhost:11434`, model `deepseek-v4-flash:cloud`).
- **UI:** NO implementada. El botón "Configuración" en `Timeline.tsx` tiene un `// TODO: settings modal` y no abre nada.
- **Health check:** `isOllamaAvailable` existe en lib/ollama.ts pero no está conectado a la UI.

### ⚠️ Requirement 2: La config de Ollama persiste
- **Persistencia:** `saveOllamaConfig` guarda en localStorage. La capa de datos persiste.
- **Uso:** `generateDailySummary` usa `getOllamaConfig()`. La config guardada se usa.
- **UI para editarla:** NO existe.

## Hallazgos

### 🟡 Hallazgo 1 (PENDIENTE): Modal de settings no implementado
La capa de datos de config Ollama existe y funciona, pero no hay UI para editarla. El botón
"Configuración" del header es un placeholder.

**Impacto:** bajo-medio. La config default funciona (Ollama en localhost:11434 con deepseek-v4-flash:cloud),
pero el usuario no puede cambiar el modelo ni la base URL sin tocar código.

**Estado:** pendiente de implementación (modal de settings).
